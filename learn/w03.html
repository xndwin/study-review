w03-1 网页产品和 API 的差别

网页 ChatGPT：厂商帮你存历史、画界面、限流、安全过滤。 应用岗写的是：你的服务器用 HTTP 调模型，再把结果接到业务（知识库、表单、内部系统）。

国内很多模型提供 OpenAI 兼容 接口：路径、字段和官方 SDK 一样，只换 base_url 和 api_key。本仓库默认 DeepSeek。换通义/Kimi/本地 vLLM，通常只改 .env 三行。

SDK（openai 包）替你做：拼 JSON、带 Header、解析响应、流式迭代。第 2 周 06_http_local.py 里的 payload 就是它发出去的东西。

w03-2 messages 与一次请求

messages = [
    {"role": "system", "content": "你是简洁的助手，用中文回答。"},
    {"role": "user", "content": "用一句话解释什么是 RAG。"},
]
role谁写的作用
system你（开发者）长期规矩：人设、格式、禁止事项。用户通常看不到
user终端用户或你的代码这一轮问题
assistant模型上一轮的话多轮时你必须原样带回去
tool你的函数返回第 7 周才用

一次调用：chat.completions.create(model=..., messages=..., temperature=..., max_tokens=...) 常用返回：choices[0].message.content，以及 usage。

公共封装：code/w03/llm.py。 跑：python code/w03/01_chat.py

w03-3 token、窗口、费用

token 是模型计费和长度的单位，不是汉字个数。英文常 1 token≈0.75 词；中文常见 1 字≈1–2 token（随模型而变）。

  • prompt_tokens：你发进去的（system + 历史 + 资料）
  • completion_tokens：模型新写的
  • 账单两者都算

上下文窗口：一次请求里 messages 总长不能超过模型上限。RAG 把整本手册塞进去会爆窗口、又贵、又稀释重点——这就是为什么要检索。

粗算费用：看服务商单价 × token / 1000 或 / 百万。应用里要对长文档做截断或检索，而不是「全塞」。

01_chat.py 会打印 usage。

w03-4 多轮

无状态： 每次 HTTP 彼此独立。网页能「记住」是因为前端/服务器把历史再次发给模型。

你要做的：

  1. 准备 history 列表，先放 system
  2. 用户一句 → append user
  3. 调接口 → append assistant（content 原样）
  4. 下一轮把整个 history 发出去

历史太长时要截断（留 system + 最近 N 轮），否则超窗口。本周先不截，但要知道这件事。

跑：python code/w03/02_multi_turn.py（输入 quit 结束）

w03-5 流式

非流式：等模型全部生成完才返回，用户干等。 流式：stream=True，每次拿到一小段 delta.content 就打印或推给前端。

跑：python code/w03/03_stream.py

注意：流式时 usage 有的供应商只在最后一块给，有的要另开非流式统计。

w03-6 常用参数

参数含义
temperature0～0.3 稳、适合问答抽取；偏高更散、适合草稿
max_tokens限制输出长度，也限制费用；太小会截断句子

tools第 7 周；声明函数给模型选

w03-7 失败与重试

情况常见原因应用里怎么做
401Key 错或没带检查 .env，不要把 Key 打进日志
402/429欠费或限流退避重试；提示用户稍后
超时网络或模型慢设 timeout；流式可先出字
5xx服务端重试有限次

llm.py 把 SDK 异常包成 RuntimeError 并保留因果。产品里还要返回给用户一句人话，而不是整段 Traceback。

.env 变量：LLM_API_KEY LLM_BASE_URL LLM_MODEL。.env 已在 gitignore。
