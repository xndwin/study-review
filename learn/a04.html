第 4 周：测试、日志、反馈清洗

计划日期：2026-12-07 到 2026-12-13。

这一周做训练项目「反馈清洗器」。从一段需求出发，你要能自己补一个功能，并为正常数据、空数据、坏数据写测试。

类型注解是给人看的

注解不自动挡掉错误输入，测试和校验才挡。它让函数签名说清输入和输出。

float | None 表示可能是小数，也可能没有结果。

日志

进行中的说明用 logging，不要全靠 print。print 留给真正要给用户看的结果。

日志里不写密钥。等级从低到高常用 DEBUG、INFO、WARNING、ERROR。

pytest

测试文件名用 test_*.py，函数名用 test_ 开头。断言失败时 pytest 会打出两边的值。

运行：python -m pytest。一个测试只查一件事。正常、空、坏数据分成三个测试，失败时才知道是哪一种。

清洗器要做什么

数据是你自己编的 CSV 或 JSON，先几十条，再造大约 1000 条。字段至少有：编号、产品、类别、问题描述、联系方式。

规则：

  • 编号相同的只留第一条。
  • 产品、类别、问题描述去掉首尾空白后不能是空。空的记入错误清单，不进入结果。
  • 类别只允许固定的几个词，例如「故障」「咨询」「建议」。不认识的记入错误清单。
  • 结果写到新文件：clean.json 和 errors.json。源文件只读。
  • 错误清单里要有原行号和原因，方便你回头看。

配置放在一个小的 JSON 或 .env.example 里，例如允许的类别、输入路径、输出路径。README 写三步：建虚拟环境、准备一份样例、运行命令和测试命令。

测试至少三条：

  • 两行编号相同，结果里只剩一行。
  • 空文件或零行，结果是空列表，程序不崩。
  • 一行缺问题描述，它出现在错误清单，不出现在清洗结果。

验收：别人只给你一句新需求，例如「问题描述短于 4 个字也算错误」，你能补上这个判断并加一个测试，旧的三个测试仍然通过。
