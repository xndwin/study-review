# 第 19 周：LangGraph 暂停与恢复

计划日期：2027-03-22 到 2027-03-28。

第 18 周的流程已经能跑。这一周把它迁到 LangGraph：状态、节点、边，确认那一步用 `interrupt()`。存档必须落盘。进程重启后，用原来的 `thread_id` 恢复。

## 图里有什么

节点是函数，例如分类、查询、写草稿、等待确认、执行更新。边决定下一个节点。状态是一份字典，在节点之间传递，里面有工单编号、草稿、是否已确认。

人要做决定时，在那个节点里面调用 `interrupt()`，把草稿版本交给外面。图停住。人提交决定后，用 `Command(resume=...)` 从停下的地方继续，不要新开一个空线程假装已经确认。

编译图时带上会落盘的 checkpointer。学习用 SQLite。只放在内存里的存档，进程一关就找不回来。

每次调用带同一个 `thread_id`，例如 `ticket-15`。恢复时还是这个 id，才能读到上次的草稿。

```python
from langgraph.types import Command, interrupt

def wait_for_human(state):
    decision = interrupt({"draft_id": state["draft_id"]})
    return {"approved": bool(decision.get("approve"))}
```

`interrupt` 的返回值，就是你稍后 `Command(resume={"approve": True})` 送回去的那个决定。节点不要自己假装已经拿到了同意。

编译时带上落盘的 checkpointer，调用时带上线程编号：

```python
graph = builder.compile(checkpointer=sqlite_saver)
config = {"configurable": {"thread_id": "ticket-15"}}
graph.invoke({"ticket_id": 15}, config)
graph.invoke(Command(resume={"approve": True}), config)
```

`sqlite_saver` 用你安装的那个 SQLite checkpointer 类来建，指向一个项目里的数据库文件。第二次 `invoke` 必须还是 `ticket-15`。
