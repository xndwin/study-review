先有一条不花钱的词匹配，再接真实 embedding 和 FAISS。向量存在 FAISS 里，原文和权限存在数据库里。两边用同一个块编号对应。

## 词匹配基线

把问题和块都切成词或字。练习阶段中文可以按字，也可以按你写明的简单规则。重叠程度：

```python
def jaccard(query: str, chunk: str) -> float:
    a, b = set(query), set(chunk)
    if not a or not b:
        return 0.0
    return len(a & b) / len(a | b)
```

取出分数最高的前 k 块，记下分数。这条结果是基线。后面向量检索好不好，要和它比，不是只看向量自己的第一名。

## 向量和模型名

调用供应商的 embedding 接口，把每一块变成向量。索引旁边写上当天文档里的模型名和向量维度。换模型或换维度，就重建索引。旧向量和新向量不能混在同一次搜索里。

FAISS 负责按向量找最近的编号。它不保存「这是哪一页、属于哪个用户」。搜到编号之后，回数据库取原文。数据库说这份已经删除，就丢掉这个编号。

```python
def search(query: str, k: int = 5) -> list[dict]:
    hits = vector_index.search(embed(query), k)
    rows = []
    for chunk_id, score in hits:
        row = db.get_chunk(chunk_id)
        if row and row["active"]:
            rows.append({"text": row["text"], "source": row["source"], "score": score})
    return rows
```

`embed` 使用的模型名必须和建索引时记下的名字相同，不同就拒绝搜索并提示重建。

口头上要能对比：FAISS 是进程里的向量文件；Milvus、pgvector 是把向量放进独立服务或数据库。这一项目用 FAISS。不要求再部署第二套向量库。
