第 6 周：SQLite 表、联表、事务

计划日期：2026-12-21 到 2026-12-27。

服务重启之后工单还在。你要能写出一条联表查询、一条聚合，并说明什么时候需要事务。

两张表

一张用户，一张工单。工单用 user_id 指向用户，这就是外键。主键是这张表里不会重复的那一列。

CREATE TABLE users (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL
);

CREATE TABLE tickets (
  id INTEGER PRIMARY KEY,
  user_id INTEGER NOT NULL,
  title TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'open',
  FOREIGN KEY (user_id) REFERENCES users(id)
);

SQLite 默认不强制外键。连接之后先执行 PRAGMA foreign_keys = ON;。

插入用参数，不要把用户输入拼进 SQL 字符串。sqlite3 的占位符是 ?。

conn.execute(
    "INSERT INTO tickets (user_id, title, status) VALUES (?, ?, ?)",
    (user_id, title, "open"),
)

"SELECT * FROM tickets WHERE title = '" + title + "'" 这种写法，标题里一旦有引号就能改变语句。参数化是把值和语句分开，不是多加一层引号。

联表和聚合

查某张工单属于谁：

SELECT tickets.id, tickets.title, users.name
FROM tickets
JOIN users ON users.id = tickets.user_id
WHERE tickets.id = ?;

JOIN 只保留两边对得上的行。用户被删了而工单还在时，这张工单不会出现。学习阶段先保证不删仍有工单的用户。

每个用户有多少张未关闭工单：

SELECT users.name, COUNT(tickets.id) AS open_count
FROM users
LEFT JOIN tickets
  ON tickets.user_id = users.id AND tickets.status = 'open'
GROUP BY users.id;

LEFT JOIN 保留没有工单的用户，计数是 0。COUNT(tickets.id) 不把配不上的空行算进去；COUNT(*) 会把用户那一行也算上，没有工单的人会变成 1。这个差别要能讲出来。

筛选加分页：WHERE status = ? ORDER BY id LIMIT ? OFFSET ?。OFFSET 是跳过前几条，页码从 0 开始算时，第 2 页、每页 20 条，就是 LIMIT 20 OFFSET 20。

事务

事务把多步改动绑成一次成功或一次失败。例如关闭工单的同时写一条操作记录：两句 INSERT / UPDATE 都成功才 commit，中间出错就 rollback，避免工单已关闭但记录没写上。

只读一条 SELECT 不需要自己开事务。下面这种「先读再改」才需要：

with conn:
    row = conn.execute("SELECT status FROM tickets WHERE id = ?", (ticket_id,)).fetchone()
    if row is None or row["status"] != "open":
        raise ValueError("不能关闭")
    conn.execute("UPDATE tickets SET status = 'closed' WHERE id = ?", (ticket_id,))
    conn.execute(
        "INSERT INTO ticket_events (ticket_id, action) VALUES (?, ?)",
        (ticket_id, "close"),
    )

with conn 正常结束会提交，抛异常会回滚。

索引：如果总是按 user_id 查这个人的工单，可以 CREATE INDEX idx_tickets_user ON tickets(user_id);。数据量还是练习规模时，索引是为了会写、会解释，不是为了宣称变快。

  • 建用户表和工单表。
  • 创建、查询、列表、修改都走 SQL。
  • 列表支持按状态筛选和分页。
  • 提供一个统计接口或命令：每个用户的未关闭工单数。
  • 停掉进程再启动，刚才那张工单还在。
