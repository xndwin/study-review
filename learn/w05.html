对应 w05-1 … w05-6。先跑通链路，向量是同一骨架换打分函数。

2026-11-17 补充：项目保持「先检索再生成」。词匹配和向量两路合并后再生成。索引记下 embedding 模型名，换模型就重建。厂商自带的网页搜索不代替这份知识库。详见 现行学法。

w05-1 为什么要 RAG

模型权重里没有你的制度、实验记录、内部接口说明。它也不会在调用时自动上网（除非你接工具）。

三种改知识的办法：

办法做什么代价
把全文塞进 prompt简单超窗口、贵、检索不准
微调改权重贵、慢、知识一变就要再训
RAG先检索再生成工程量大，但可更新文档

RAG = Retrieval-Augmented Generation：检索增强生成。

RAG 不解决：模型算术不稳、需要操作外界（那是工具）、需要固定语气（微调更合适）。

流水线：

文档 → 切块 → 索引 → 问题 → Top-K 块 → 拼进 prompt → 生成（带引用）

w05-2 切块与 overlap

检索的单位是块，不是整篇。

  • chunk_size 太大：一块里噪声多，打分钝
  • 太小：句子从中切开，缺主语
  • overlap：块与块重叠一段，避免答案落在切缝上丢失

实现：chunk_text（按字符滑动窗口）。工业界还会按标题/段落切，中文可用更认真的分词。本周先把窗口做对。

跑 demo 时看打印出来的块边界是否把同一句话劈开。

w05-3 词重叠检索（可跑通）

不依赖 embedding 接口：把问题和块切成英文单词 + 连续两字中文，算 Jaccard：

\[ score = |Q \cap C| / |Q \cup C| \]

取 Top-K 且分数 > 0。没有交集就视为没检索到。

这不是搜索引擎，但接口已经是 retrieve(query) -> list[(Chunk, score)]。后面换向量不改生成代码。

w05-4 向量、embedding、余弦相似度

embedding：把一段文本变成长度为 d 的浮点向量，语义近的点夹角小。

余弦相似度（向量 a、b，模长非 0）：

\[ \cos(a,b) = (a \cdot b) / (|a| |b|) \]

范围约 -1～1，越接近 1 越相似。检索：对每个块算与问题的余弦，取最大的 k 个。

本仓库用词袋向量 + 余弦演示公式（不调用付费 embedding API）。词袋：词空间每一维是该词出现次数。这和神经网络 embedding 不同，但余弦计算一模一样。

有 OpenAI 兼容 embedding 接口时，只需把「造向量」换成 client.embeddings.create，检索函数不用改形状。

跑：python code/w05/02_compare.py 对比两种打分。

w05-5 带引用生成与拒答

prompt 里给块编号：

[1] 来源 notes.md：……
[2] 来源 about.md：……

规矩：只根据资料；不足则说「资料中没有」；用到的句子末尾标 [编号]。

检索为空时，build_prompt 会写入「没有检索到资料」，生成侧仍可能胡编，所以还要用评测盯住。产品里也可以检索为空时不调生成，直接返回固定拒答。

跑：python code/w05/01_rag_demo.py

w05-6 失败模式

现象常见原因处理
胡编空检索仍让模型自由发挥拒答或强制只据资料
答非所问切块差、K 太小、词重叠对同义句弱换切法/K/向量
答案缺半句切在句子中间且 overlap 不够加大 overlap 或按句切
引用错号模型没严格执行后处理核对编号是否在 hits 里
全篇都一般相关文档太同质或问题太泛让用户问具体一点；加标题进块
