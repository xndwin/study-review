# 第 23 周：回归测试与故障复盘

计划日期：2027-04-19 到 2027-04-25。

每次改代码，先跑一批不调用付费 API 的检查。两个项目各写 3 个故障案例。案例里有怎样复现、怎样发现、怎样修复。

## 哪些测试进自动检查

放进自动检查的：

- 字段校验、状态机、权限、幂等。
- 用假的模型响应走工具循环。
- 检索在一份小的本地样本上能找回标好的那一块。

不放进去的：

- 真实供应商调用。
- 需要密钥才能过的测试。

本地命令仍然是 `python -m pytest`。如果要接一个托管的持续集成，就用仓库里的配置，在推送时跑上面这一组。密钥用仓库的加密变量，示例配置里不放真密钥。没有托管账号时，这一周先把命令写进 README，每次修改前在本地跑，也算数。笔记里写你实际怎么跑的。

## 故障案例的格式

每个案例六行：

1. 日期和项目。
2. 你看到的现象。
3. 复现步骤。
4. 原因，具体到文件和判断。
5. 修复。
6. 哪一个测试能防止它再出现。

例如：确认接口被调用两次，工单状态被改了两次。原因是更新前没有看幂等标记。修复是第 18 周的那次检查。测试是连续发送同一确认编号，第二次状态不再变化。

三个案例来自你真实遇到的问题。还没有三起时，就在测试环境里故意制造：删掉环境变量、把一块文档标成删除仍留在索引里、工具返回错误。制造的也要写明是演练。

## 这一周自己写

两个项目各自有一条命令可以跑完免费测试。六个案例落在 `docs/incidents.md`，可以两个项目分开文件。

验收：你改坏幂等或权限时，测试会失败。真实 API 的脚本要手动另跑，不会在这条自动命令里被触发。
