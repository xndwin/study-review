第 16 周：分层评测与可启动版本

计划日期：2027-03-01 到 2027-03-07。

冻结测试集，写出评测报告，交出别人能启动的版本。通过之后可以开始投实习。对照 Dify 或 RAGFlow 最多 4 小时，用来看一家可视化产品怎样展示来源，不把项目改成那家的配置。

两列分数

每道题分开记：

  • 检索：前 5 个块里有没有标好的证据。这叫 Hit@5。
  • 回答：回答里的事实是不是都被引用块支持。这由你逐题看。

无答案的题只统计该不该拒答。跨片段的题还要看：需要的证据是不是都在，少一块也算没找齐。

不要把这些合成一个总分。报告写原始计数，例如「单文档证据 8/10」。

题目大约 100 条：单文档 50、跨片段 20、无答案 20、对抗或权限 10。开发集 60，保留集 40。保留集不拿来反复改提示和参数。

练习目标是保留集上：单文档 Hit@5 尝试达到 80%，回答被引用支撑尝试达到 85%，无答案拒答尝试达到 80%。这是本计划的练习线，不是招聘统一标准。没达到就写清是解析、召回、生成还是标注的问题，不改测试题去凑数。

报告里有什么

  • 资料从哪来，多少份。
  • 切块长度、重叠、embedding 模型名、两路各取多少。
  • 开发集和保留集各多少，划分日期。
  • 两列计数、拒答计数、跨片段是否找齐。
  • 至少 3 个失败例子：问题、召回了什么、模型说了什么、你认为错在哪一步。

可启动

README 写：Python 版本、环境变量示例、怎样放入示例文档、怎样建索引、怎样启动接口、怎样跑不花钱的测试。路径用项目内的相对路径。

提交前在一个新终端按 README 走一遍。

这一周自己写

跑保留集，把两列数字和三个失败例子写进 eval/report.md。再用不超过 4 小时，把同一道题在 Dify 或 RAGFlow 里问一次，只记录它展示来源的方式，以及你的项目差在哪。

验收：报告不是一个笼统的百分比；别人按 README 能启动；失败例子能对应到解析、召回或生成。

写程序仍在电脑上。新开对话只发：先读 主文件.md，从书签继续。
