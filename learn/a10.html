第 10 周：结构化输出与字段校验

计划日期：2027-01-18 到 2027-01-24。

把一段反馈提取成类别、产品、问题描述。模型不确定时留空或转人工。JSON 格式对了，不等于内容可以用。

三个字段

fields = {
    "kind": "故障",
    "product": "校园网",
    "detail": "宿舍连不上",
}

类别只允许「故障」「咨询」「建议」。产品和要求描述去掉空白后不能是空，除非你明确标记「转人工」。

先用 schema，不行再退一步

供应商支持时，response_format 用 json_schema，并打开严格模式。这样模型更不容易漏字段或加字段。

不支持时，退到 json_object，或者在提示里要求只输出一个 JSON 对象。json_object 只保证整体是 JSON，不保证有 kind 这个键，也不保证 kind 属于那三个词。

两种都要在你的代码里再查一遍：

import json

ALLOWED = {"故障", "咨询", "建议"}

def accept(raw: str) -> dict:
    data = json.loads(raw)
    kind = data.get("kind")
    product = str(data.get("product") or "").strip()
    detail = str(data.get("detail") or "").strip()
    if kind not in ALLOWED:
        raise ValueError("未知类别")
    if not product or not detail:
        raise ValueError("缺字段")
    return {"kind": kind, "product": product, "detail": detail}

业务规则不交给 schema 一个人管。例如「描述至少 4 个字」仍写在 accept 里。

模型有时用 Markdown 代码块包住 JSON。json.loads 之前，如果文本以三个反引号开头，先去掉首尾的围栏行。去完仍不是 JSON，就拒绝，不要把原文直接存成提取结果。

提示词写成仓库里的一个文本文件，一次只做提取这一件事。少样本最多放两个，一个正常，一个应当转人工。样本和评测题不要用同一句。

不确定就不要猜

提示里写明：无法判断类别时，kind 用空字符串，不要选一个最像的。你的代码看到空字符串，状态记为「转人工」，不写入已分类结果。

非法 JSON、缺字段、未知类别，三条路径都要有测试。测试用你写死的模型响应字符串，不调用付费接口。

两家分别记录

同一套 accept，分别用两家供应商跑。在笔记里写：这家支持严格 json_schema，还是只支持 json_object，还是只能靠提示。不支持就走退路，不要假装两家能力一样。

这一周自己写

输入一句反馈，输出三个字段或「转人工」。

准备这些假响应做单元测试：

  • 合法 JSON，三个字段都对。
  • 缺 detail。
  • kind 是「投诉」，不在允许列表里。
  • 外面包了一层代码围栏。
  • 空的 kind，结果是转人工，不是随便归进「咨询」。

验收：非法结果被代码拒绝；你能说出 schema 挡的是形状，代码挡的是业务规则。
