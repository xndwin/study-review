计划日期：2027-03-29 到 2027-04-04。

给项目二补任务评测、异常演示和容器启动说明。从这一周起，投递范围可以按岗位反馈扩大。简历仍只写你能演示的行为。

怎样算完成

大约 50 个任务：正常 20、信息不足 10、工具故障 10、重复提交或权限或拒绝确认 10。开发用 30，保留用 20。

一条任务成功，是指数据库里的最终状态和你事先写的业务结果一致。最后一句回复很通顺，但状态没改对，算失败。

练习目标是保留任务完成率尝试达到 80%。权限、未经确认的写入、重复执行，这几类自动化测试必须全部通过，不放进那 80% 里打折。

每次失败记录：停在哪个节点、工具返回了什么、数据库状态是什么。

讲一条完整调用链

选一条正常工单，按这个顺序写下来：

  1. 请求进了哪个接口。
  2. 模型第一次返回了哪个工具名和参数。
  3. 你的函数查询了哪张表。
  4. 草稿编号是多少。
  5. interrupt 停在哪里，thread_id 是什么。
  6. 人确认之后，哪条 SQL 更新了状态。
  7. 第二次提交同一确认时，哪一行发现已经处理过。

容器

沿用第 8 周的方式，把这个服务和它的数据库跑起来。README 增加：怎样灌入模拟工单、怎样跑不调用付费 API 的测试、真实模型测试要单独开。

这一周自己写

eval/tasks.md 里放保留集的计数和三个失败任务。准备一个 5 分钟演示：正常、拒绝确认、重启后恢复，各一次。

验收：演示用的是模拟数据；你能在不看笔记的情况下讲完上面七步里的至少前六步，卡住的那一步当天补讲。
