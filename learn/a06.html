服务重启之后工单还在。你要能写出一条联表查询、一条聚合，并说明什么时候需要事务。

两张表

一张用户，一张工单。工单用 user_id 指向用户，这就是外键。主键是这张表里不会重复的那一列。

SQLite 默认不强制外键。连接之后先执行 PRAGMA foreign_keys = ON;。

插入用参数，不要把用户输入拼进 SQL 字符串。sqlite3 的占位符是 ?。

"SELECT * FROM tickets WHERE title = '" + title + "'" 这种写法，标题里一旦有引号就能改变语句。参数化是把值和语句分开，不是多加一层引号。

每个用户有多少张未关闭工单：

LEFT JOIN 保留没有工单的用户，计数是 0。COUNT(tickets.id) 不把配不上的空行算进去；COUNT(*) 会把用户那一行也算上，没有工单的人会变成 1。这个差别要能讲出来。

筛选加分页：WHERE status = ? ORDER BY id LIMIT ? OFFSET ?。OFFSET 是跳过前几条，页码从 0 开始算时，第 2 页、每页 20 条，就是 LIMIT 20 OFFSET 20。

事务

事务把多步改动绑成一次成功或一次失败。例如关闭工单的同时写一条操作记录：两句 INSERT / UPDATE 都成功才 commit，中间出错就 rollback，避免工单已关闭但记录没写上。
