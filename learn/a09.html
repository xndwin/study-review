第 9 周：两家模型 API

2026-11-17 两套都要认识网页产品和 API历史要自己存流式失败这一周自己写

计划日期：2027-01-11 到 2027-01-17。

同一套代码分别接两家 OpenAI 兼容供应商，只改配置。对话历史由你保存。换供应商之后，已经说过的话还在。鉴权失败、超时、限流都有上限和中文说明。

调用形状以 现行学法 为准，日期看那一页。2026-11-17 的核对结果写在下面。

2026-11-17 两套都要认识

两家互换的作业用 Chat Completions：messages、tools、stream、response_format。通义当天帮助页仍把它当作兼容入口，DeepSeek 也还提供这条路径。

OpenAI 规定自家新项目用 Responses。DeepSeek 同样有 POST /responses。Assistants API 已于 2026-08-26 停用，不要学 threads、assistants 那套旧教程。

这段的结果在 output_text，不在 choices[0].message.content。流式事件也不同，两套解析不要抄到一起。通义若当天没有 Responses，这一段只在有该接口的供应商上跑；互换作业仍走 Chat Completions。

模型名放进环境变量，从当天模型列表抄。DeepSeek 文档这天的示例是 deepseek-flash。参考脚本里的 deepseek-chat 是旧例子，不写进新代码。思考开关按供应商文档放：DeepSeek 用 thinking，通义放在 extra_body。厂商自带的网页搜索是公开网页能力，不是第 13 周你自己的知识库。

网页产品和 API

网页聊天的历史存在厂商那边。API 每次都是新请求，厂商不记得上一次。你要把之前的 user 和 assistant 消息放进下一次的 messages。

role谁写的
system你，规定人设和格式
user用户这一轮
assistant模型上一轮的原文
tool你的函数返回，第 17 周再用

一次非流式调用取正文：response.choices[0].message.content。用量在 response.usage，里面有 prompt_tokens 和 completion_tokens。两个都计费。token 不是汉字个数。

配置只放三个值：base_url、api_key、model。密钥从环境变量读。日志最多打密钥前四位。.env 不提交，仓库里只留 .env.example 的占位符。

两家例如 DeepSeek 和通义，或你账户里实际开通的两家。切换时改配置，不改对话循环。

历史要自己存

complete 里面才是真正的 HTTP 调用。先问「我叫王敏」，再问「我刚才说我叫什么」。第二问的 messages 里必须有第一问和模型的回答，否则模型看不到名字。

历史太长就丢掉最早的用户轮次，保留 system。窗口和费用在这里开始变得具体：每轮都会把旧消息再发一遍。

流式

流式时正文在增量里，不在最终的 message.content。Chat Completions 的增量是 chunk.choices[0].delta.content，有的块是空的，跳过再拼接。

这段拼接结果也要写回 history，否则下一轮仍然没有模型刚才说的话。

失败

现象含义你怎么做
401密钥不对或没带立刻失败，提示检查密钥，不要重试十几次
429限流最多重试 2 次，间隔拉开
超时网络或模型太慢最多重试 2 次，然后告诉用户稍后再试
5xx对方服务故障同样设上限

重试次数写在配置里。最后一次仍失败，抛出一个你自己的错误，消息是中文，里面没有密钥、没有整段 HTML 报错。

这一周自己写

一个命令行对话：

  • 环境变量选择供应商 A 或 B。
  • 连续两轮，第二轮能用到第一轮的内容。
  • 把同一段历史换到另一家，回答可以不同，但历史不能丢。
  • 故意写错密钥，看到中文提示，而不是把密钥打出来。
  • 记录一次成功调用的 prompt_tokens 和 completion_tokens。

模型名从你选定的供应商当天文档抄，不写已经停用的旧名字。
