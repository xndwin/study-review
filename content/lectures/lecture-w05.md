## w05-1 为什么要 RAG

模型权重里没有你的制度、实验记录。三种改知识的办法：

| 办法 | 做什么 | 代价 |
|------|--------|------|
| 全文塞进 prompt | 简单 | 超窗口、贵、不准 |
| 微调 | 改权重 | 贵、慢、知识一变再训 |
| RAG | 先检索再生成 | 工程量大，但可更新文档 |

RAG = 检索增强生成。**不**解决：算术不稳、要操作外界（工具）、要固定语气（微调更合适）。

```
文档 → 切块 → 索引 → 问题 → Top-K 块 → 拼进 prompt → 生成（带引用）
```

```bash
python3 code/test/w05_1_why_rag.py
```

## w05-2 切块与 overlap

检索单位是块，不是整篇。`chunk_size` 太大：噪声多、打分钝。太小：句子从中切开。`overlap`：块与块重叠一段，避免答案落在切缝上丢失。实现是按字符滑动窗口。工业界还会按标题/段落切。

```bash
python3 code/test/w05_2_chunk.py
```

## w05-3 词重叠检索（Jaccard）

不依赖 embedding 接口：问题和块切成英文单词 + 连续两字中文。

score = |Q ∩ C| / |Q ∪ C|

取 Top-K 且分数 > 0。没有交集视为没检索到。接口已经是 `retrieve(query) -> list[(Chunk, score)]`，后面换向量不改生成代码。

```bash
python3 code/test/w05_3_jaccard.py
```

## w05-4 向量、embedding、余弦

embedding：文本 → 长度为 d 的浮点向量，语义近的夹角小。

cos(a,b) = (a · b) / (|a| |b|)

范围约 -1～1，越接近 1 越相似。本仓库用**词袋向量 + 余弦**演示公式（不调付费 embedding）。词袋：每一维是词出现次数。和神经网络 embedding 不同，但余弦计算一模一样。有 embedding 接口时，只换「造向量」这一步。

```bash
python3 code/test/w05_4_cosine.py
python3 code/test/w05_compare.py
```

## w05-5 带引用生成与拒答

prompt 里给块编号 `[1] 来源 notes.md：……`。规矩：只根据资料；不足说「资料中没有」；用到的句子末尾标编号。

## w05-6 失败模式

| 现象 | 常见原因 | 处理 |
|------|----------|------|
| 胡编 | 空检索仍自由发挥 | 拒答或强制只据资料 |
| 答非所问 | 切块差、K 太小、同义句弱 | 换切法/K/向量 |
| 答案缺半句 | 切在句中且 overlap 不够 | 加大 overlap 或按句切 |
| 引用错号 | 模型没严格执行 | 后处理核对编号是否在 hits |
| 全篇都一般相关 | 文档太同质或问题太泛 | 问具体一点；加标题进块 |
