# 第 17 周：工具调用

计划日期：2027-03-08 到 2027-03-14。

项目二处理模拟售后工单：查询规则和状态，生成处理草稿，等人确认之后才改数据库。数据和业务都是模拟的。

这一周用普通 Python 把「分类 → 查询 → 生成草稿」跑通，接上至少 3 个受控工具。简历上这一周可以叫做工具调用。ReAct 只是讲解时的词，指模型交替想下一步和查看工具结果。代码不必先上某个 Agent 框架。

## 谁执行工具

你声明工具的名字、说明和参数 schema。模型返回它想调用的名字和参数。真正执行的是你的 Python。模型进不了你的电脑，也不能自己写 SQL。

旧字段 `function_call` 不要照抄。现在用 `tools` / `tool_calls`。

循环是：

1. 把 `tools` 和当前 `messages` 发给 Chat Completions。
2. 如果 `message.tool_calls` 是空的，`content` 就是给用户的话，结束。
3. 否则解析每个调用的 JSON 参数，在白名单里找函数。
4. 把模型那条消息放回历史，再追加 `role` 为 `tool` 的结果，带上 `tool_call_id`。
5. 再请求，直到没有工具调用，或达到最大步数。

白名单之外的名字，返回「没有这个工具」，不要用 `getattr` 去摸任意函数。

## 三个工具

先做这三个，都只读或只产生草稿：

- `get_ticket(ticket_id)`：返回这张模拟工单的状态和用户。
- `get_policy(topic)`：从你写的短政策里查一条。
- `save_draft(ticket_id, text)`：把草稿存起来，不改变工单状态。

参数先校验。`ticket_id` 不是整数、政策主题不在允许列表，就返回错误字符串给模型，让它看见失败原因。不要把异常直接打成 500 结束整个循环。

计算器如果要做，只用语法树允许数字和 `+ - * / **`，不用 `eval`。读文件必须先 `resolve`，确认路径落在指定目录里，拒绝 `../.env`。

## 规则和模型各管什么

模型负责从工单文字里提出「可能是退款」这种分类，并起草一段话。能不能退、状态能不能从 open 改成 refunded，由你的代码查表决定。模型说「可以退款」不会让数据库更新。

## 这一周自己写

用一条模拟工单跑完：分类结果、查到的政策原文、一份草稿。日志里能看到工具名字和参数，看不到密钥。

验收：把工具名改成白名单里没有的，循环收到错误文本而不是执行任意代码。你能指出哪一行是模型的意图、哪一行是你的函数。
