# 第 8 周：PostgreSQL、Linux、Docker

计划日期：2027-01-04 到 2027-01-10。

这一周把 SQLite 换成 PostgreSQL，并用 Docker 把服务和数据库一起启动。新环境按 README 能起来，重启容器不丢数据。你要能从日志里看出端口或配置错了。

## 换数据库时改什么

表结构思路不变。占位符变了：`psycopg` 用 `%s`，不是 `?`。连接串放在环境变量 `DATABASE_URL`，例如 `postgresql://app:app@db:5432/tickets`。代码读环境变量，不把密码写进源文件。

```python
import os
import psycopg

url = os.environ["DATABASE_URL"]
with psycopg.connect(url) as conn:
    row = conn.execute("SELECT id, title FROM tickets WHERE id = %s", (ticket_id,)).fetchone()
```

SQL 语句尽量保持普通的 `SELECT` / `INSERT` / `UPDATE`。简历上可以写：语句是在 PostgreSQL 上写的，同一类语句能搬到 MySQL，占位符和少量类型要按那家的驱动改。

## Linux 上这几条就够

在服务器或容器里：

```bash
pwd
ls
cat .env.example
ps aux | head
ss -lntp | head
```

`ss -lntp` 看谁占用了端口。`8000` 已经被占用时，服务会启动失败，日志里通常有 `address already in use`。环境变量没传进去时，程序会在读 `DATABASE_URL` 的地方失败，日志要打出「缺少 DATABASE_URL」，不要打出整段连接串，因为里面有密码。

`docker compose logs api` 看服务输出。`docker compose logs db` 看数据库。先看最后几十行。

## Compose

两份服务：`db` 用官方 PostgreSQL 镜像，`api` 用你的 FastAPI。数据库数据放在命名卷里，容器删了再创建，卷还在，数据就还在。

```yaml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: app
      POSTGRES_DB: tickets
    volumes:
      - pgdata:/var/lib/postgresql/data
  api:
    build: .
    environment:
      DATABASE_URL: postgresql://app:app@db:5432/tickets
    ports:
      - "8000:8000"
    depends_on:
      - db
volumes:
  pgdata:
```

容器里的主机名是服务名 `db`，不是 `127.0.0.1`。`127.0.0.1` 指的是 api 容器自己，上面没有数据库。

镜像构建用一个短的 `Dockerfile`：选一个 Python 3.11 基础镜像，复制依赖文件，`pip install`，再复制代码，启动命令是 `uvicorn`。工作目录和 README 里的命令一致。

`depends_on` 只保证数据库进程先启动，不保证它已经能接受连接。api 启动失败时，看日志是不是「连接被拒绝」。练习里可以在启动时重试几次连接，每次间隔一秒，最多十次，并在日志里写第几次。
