# 第 26 周：独立做一个小变更

计划日期：2027-05-10 到 2027-05-16。

给自己一个新需求，在半天里做完：实现、测试、按 README 启动，并讲给别人听。同时维持投递，跑一遍两个项目的免费回归。

## 需求要小到半天能做完

从下面选一个，或写一个同样大小的。开始前把范围写成五句话：谁用、输入、输出、拒绝什么、怎样算做完。

- 知识库：按文档版本过滤，旧版本默认不参与检索。
- 工单：增加一个「补充材料」状态，只有 open 能转到它，确认之前仍然不能变成 resolved。
- 提取：类别增加一个允许值，旧测试还要通过，缺字段仍然转人工。

半天之外的想法记下来，不在这天做。做不完就缩小范围，例如只做状态转换和测试，不改界面。

## 当天的顺序

1. 写出验收的三条测试，先看它们失败。
2. 改最少的代码让它们通过。
3. 跑这一个项目全部免费测试。
4. 按 README 在本地启动，手动走一遍新路径。
5. 用 5 分钟讲：改了哪一层，哪条测试拦住了旧行为被破坏。

讲的时候说明 AI 帮你看了哪一段、哪一段是你自己定的规则。规则和测试要是你能改的。

## 结束后的一页

写下还没掌握的三件事，每件对应后面要读的官方文档章节，不新开一条主线。Kubernetes、分布式训练、多 Agent 平台不放进这三件，除非已经拿到的录用通知把其中一项写成到岗前必须会。

投递继续。项目指标没达到练习目标时，简历写实测计数和失败分析。核心路径跑不起来、权限或未经确认就能写入、自己讲不清核心代码，就先修再拿这个项目投。

## 这一周自己写

一个小变更的说明：需求五句话、diff 涉及的文件、测试名、手动检查的结果。

验收：半天时间盒内能演示；回归命令通过；你能回答「如果再改一个相邻字段，测试要加在哪」。
