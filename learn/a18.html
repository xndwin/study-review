第 18 周：确认、幂等、失败

计划日期：2027-03-15 到 2027-03-21。

没有人工确认，就不能改工单状态。同一次确认重复提交，不能改两次。查询失败、信息不够、人拒绝、重复提交，都要有确定的结果。

状态放在数据库里

草稿、当前步骤、确认记录都写进表，不要只放在内存变量里。进程重启后，你能查到任务停在「等待确认」。

一张确认要绑定：工单编号、草稿版本、操作者、决定是同意还是拒绝。模型输出一句「用户已同意」不算确认。确认只能来自你的接口，例如 POST /drafts/15/decision，正文是 {"approve": true}，并且请求头里的用户就是这张工单的主人或指定的处理人。

幂等

同意之后的更新使用确认编号当幂等键。同一编号第二次进来：如果第一次已经成功，就返回当时的结果，不再执行 UPDATE。

占位符按驱动来：SQLite 用 ?，psycopg 用 %s。

def apply_decision(conn, decision_id: int, approve: bool):
    existing = conn.execute(
        "SELECT applied FROM decisions WHERE id = ?",
        (decision_id,),
    ).fetchone()
    if existing and existing["applied"]:
        return "已经处理过"
    if not approve:
        conn.execute("UPDATE decisions SET applied = 1, approved = 0 WHERE id = ?", (decision_id,))
        return "已拒绝"
    with conn:
        conn.execute("UPDATE tickets SET status = 'resolved' WHERE id = (SELECT ticket_id FROM decisions WHERE id = ?)", (decision_id,))
        conn.execute("UPDATE decisions SET applied = 1, approved = 1 WHERE id = ?", (decision_id,))
    return "已更新"

拒绝确认时，工单状态保持原样，草稿保留，任务标成已拒绝。

重试要分读和写

查工单、查政策可以再试。save_draft 和状态更新如果失败，先看幂等键有没有已经成功，再决定要不要重做。没有幂等键的写操作不要自动重试。

最大步数沿用工具循环，例如 6 步。到达上限就停，把最后一次工具错误写进任务记录。

信息不够时，例如工单没有订单号而政策要求订单号，就停止并说明缺什么，不要让模型编一个订单号再写入。

这一周自己写

四条路径各留一条数据库记录：

  • 查询工具返回失败，任务停住，状态没变。
  • 草稿写好了，但还没有确认，状态没变。
  • 人拒绝，状态没变。
  • 同一确认请求发送两次，状态只变一次。

验收：你能用同一条确认编号演示第二次不会再次更新。
